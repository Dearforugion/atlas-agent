# Аудит сайта

1. Определи цель: URL или домен. Если схема не указана, используй `https://`.
2. Проверь скоуп через `scope_check`:
   - локальные/приватные цели разрешены без скоупа при `allow_private_targets`;
   - публичный сайт должен быть в авторизованном скоупе.
3. Запусти `whois_lookup` (регистратор, даты, NS, DNSSEC) и `dns_lookup` (A, AAAA, MX, NS, TXT).
4. Запусти `site_audit` с URL. Инструмент соберёт:
   - HTTP-статус, редиректы, заголовки;
   - TLS-сертификат и версию TLS;
   - DNS-адреса и reverse DNS;
   - технологии по заголовкам, HTML и cookie;
   - наличие заголовков безопасности;
   - типовые пути (`robots.txt`, `sitemap.xml`, `.git/HEAD`, `.env` и др.).
5. Запусти `crawl_site` — обход страниц, сбор ссылок, форм и email.
6. Если цель локальная и нужен скан портов — используй `port_scan` (не требует nmap).
7. Если установлены внешние инструменты — `pentest_tools`, затем `pentest_run`:
   - `httpx` — живые хосты и технологии;
   - `ffuf` / `gobuster` — директории и файлы;
   - `nmap` — порты и сервисы;
   - `nuclei` / `nikto` / `sqlmap` — только активные проверки и только в скоупе.
8. Проанализируй findings по приоритету:
   - критично: открытые `.env`, `.git`, админки без авторизации, просроченный сертификат;
   - высоко: отсутствие HSTS/CSP, HTTP вместо HTTPS, раскрытие версий ПО;
   - средне: отсутствие X-Frame-Options, Referrer-Policy, Permissions-Policy;
   - низко: лишние заголовки, устаревшие технологии.
9. Дай краткий отчёт: что найдено, чем это опасно, что делать. Укажи путь к Markdown-отчёту в `workspace/reports/`.

Не атакуй цели вне разрешённого скоупа. Для публичных сайтов разрешение подтверждает человек.
