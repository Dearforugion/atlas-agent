# ATLAS — локальный автономный ИИ-агент

ATLAS — ваш персональный агент, который живёт в этой папке. Он не просто отвечает на вопросы, а **выполняет задачи**: читает и создаёт файлы, запускает команды и Python-код, ищет в интернете, ведёт долговременную память и накапливает навыки.

У агента есть:

- **личное окружение** — изолированный Python venv в `.venv`;
- **личное рабочее пространство** — папка `workspace/`, за пределы которой он не выходит без разрешения;
- **мозг** — любая OpenAI-совместимая модель: локальная (Ollama, LM Studio) или облачная;
- **память** — факты, которые сохраняются между запусками;
- **навыки** — markdown-методики, которым его можно обучать;
- **журнал действий** — `data/audit.log`, всё фиксируется;
- **режим автоматизации** — папка `inbox/`: кладёте задачу файлом, получаете результат в `outbox/`;
- **параллельные воркеры** — инструмент `subagent`: несколько копий агента за разные подзадачи (хосты, поддомены) работают параллельно;
- **живой прогресс** — пока модель думает или выполняется инструмент, в консоли видно текущий шаг, действие, прогресс-бар и оценку «ост. ~Nс»;
- **главное меню** — дашборд со всеми навыками, ролями-агентами, инструментами, скоупом и памятью в одном месте.

---

## Быстрый старт

Самый простой запуск — двойной клик по **`start.bat`**. Скрипт сам:

1. создаст `.venv`, если его нет;
2. запустит Ollama и создаст модель `atlas`, если их нет;
3. прогонит диагностику;
4. откроет **главное меню** — дашборд со всеми возможностями агента.

В меню:

- слева — быстрые действия: чат, разовая задача, агенты, навыки, инструменты, скоуп, память, параллельные задачи, диагностика;
- справа — список навыков и готовых ролей;
- сверху — модель, статус скоупа, количество фактов, навыков, агентов и инструментов;
- управление — стрелки (или `j`/`k`), цифры `1–9`, `0` — выход; `Enter` — выбрать, `Esc`/`q` — назад.

Можно передать задачу сразу:

```powershell
.\start.bat "сделай аудит http://127.0.0.1:11434/"
```

Ручной запуск:

```powershell
# 1. Создать личное окружение и проверить систему
powershell -ExecutionPolicy Bypass -File .\setup.ps1

# 2. Подключить модель (см. ниже)

# 3. Проверить связь
.\run.cmd doctor

# 4. Открыть главное меню
.\run.cmd menu

# Либо сразу чат
.\run.cmd
```

На этом компьютере уже всё настроено: Ollama запущен, модель `atlas` (qwen3:8b, контекст 12k, flash-attention) скачана, `config.json` указывает на неё. Пентест-возможности и работа с публичными целями описаны в `PENTEST.md`.

Без модели можно проверить сам движок:

```powershell
.\run.cmd selftest
```

Автотест создаёт временную папку, вызывает инструменты через тестовую модель и проверяет изоляцию, память, shell и Python. Внешний ИИ для него не нужен.

## Подключение модели

Движок поддерживает любой API формата OpenAI: `/v1/chat/completions` и `/v1/models`.

### Текущая установка

- Ollama 0.40.16, сервер на `http://127.0.0.1:11434`;
- модель `atlas:latest` — это `qwen3:8b` с контекстом 12 288 токенов, режимом рассуждения и настройками сэмплинга для планирования (см. `Modelfile`); flash-attention и q8_0 KV-кэш включены в `start.bat`, чтобы модель целиком помещалась в 8 ГБ VRAM;
- `config.json` уже указывает на `atlas:latest`.

Проверить: `.\run.cmd doctor`. Пересоздать модель после изменения `Modelfile`:

```powershell
ollama create atlas -f .\Modelfile
```

### Вариант 1. Ollama — локально и бесплатно (рекомендуется)

```powershell
winget install Ollama.Ollama
ollama pull qwen3:8b
ollama create atlas -f .\Modelfile
```

В `config.json`:

```json
"llm": {
  "base_url": "http://127.0.0.1:11434/v1",
  "api_key": "ollama",
  "model": "atlas:latest",
  "native_tools": true
}
```

По умолчанию стоит `qwen3:8b` — целиком влезает в 8 ГБ VRAM и заметно сильнее в планировании и многошаговых задачах, чем прежний `qwen3:4b`. Если видеопамяти больше, можно взять `qwen3:14b` или `qwen2.5:14b` (ещё умнее, но медленнее и частично уходит в ОЗУ). Для слабого компьютера подойдёт `qwen3:4b` — быстрее, но ошибается чаще. Любая модель должна поддерживать вызов инструментов.

### Вариант 2. LM Studio

Включите в LM Studio Local Server (порт 1234) и укажите:

```json
"base_url": "http://127.0.0.1:1234/v1",
"api_key": "lm-studio",
"model": "<id модели из списка>"
```

### Вариант 3. Облачный API

Подходит OpenAI, OpenRouter, DeepSeek, Groq и другие. Ключ лучше не хранить в файле, а задать переменной окружения:

```powershell
setx AGENT_API_KEY "sk-..."
```

Затем в `config.json`:

```json
"base_url": "https://api.openai.com/v1",
"api_key": "",
"model": "gpt-4.1-mini"
```

`AGENT_API_KEY`, `AGENT_MODEL` и `AGENT_BASE_URL` переопределяют значения из конфига.

Проверка: `.\run.cmd doctor` покажет список доступных моделей.

## Как пользоваться

```powershell
.\run.cmd menu                           # главное меню (дашборд)
.\run.cmd                                # интерактивный чат
.\run.cmd ask "создай проект на Python и запусти тесты"
.\run.cmd ask --yes "наведи порядок в workspace"
.\run.cmd ask --agent scout "проверь DNS и TLS example.com"
.\run.cmd ask --agent auditor --skill site-audit "аудит https://example.com"
.\run.cmd daemon                         # автоматизация через inbox/
```

Готовые роли: `atlas`, `scout`, `pentester`, `auditor`, `researcher`, `coder`, `sysadmin`. Роль задаёт стиль работы, а навык автоматически попадает в системный промпт.

В интерактивном режиме:

| Команда | Что делает |
|---|---|
| `/help` | справка |
| `/reset` | забыть контекст диалога |
| `/yes` | вкл/выкл авто-подтверждение опасных действий |
| `/agents` | список готовых ролей-агентов |
| `/agent <id>` | переключить роль (например, `scout`) |
| `/model <id>` | сменить модель на сессию |
| `/memory [n]` | последние факты памяти |
| `/skills` | список навыков |
| `/skill <name>` | показать навык |
| `/use <name>` | подключить навык к текущей сессии |
| `/teach <факт>` | сохранить факт в память |
| `/scope` | показать авторизованный скоуп |
| `/session` | путь журнала сессии |
| `/exit` | выход |

### Прогресс и оценка времени

Во время работы под каждой задачей видна строка состояния: текущий шаг, имя инструмента, прошедшее время, прогресс-бар и оценка «ост. ~Nс». ATLAS запоминает реальные длительности ответов модели и инструментов в `data/metrics.json` и постепенно уточняет оценку. Если фаза идёт дольше обычного, вместо времени появится «дольше обычного». По завершении печатается сводка: общее время и число шагов.

### Готовые роли

Роль не меняет инструменты и права — она добавляет в системный промпт инструкцию и, если указан, навык. Переключение: `--agent <id>` в командной строке, `/agent <id>` в чате или пункт «Агенты и роли» в меню.

| id | Роль | Для чего | Навык |
|---|---|---|---|
| `atlas` | ATLAS | универсальный режим | — |
| `scout` | Разведчик | DNS, WHOIS, TLS, порты, карта цели | `pentest-methodology` |
| `pentester` | Пентестер | полный цикл авторизованного теста | `pentest-methodology` |
| `auditor` | Аудитор сайтов | заголовки, TLS, DNS, технологии, отчёт | `site-audit` |
| `researcher` | Исследователь | поиск, проверка фактов, выжимка со ссылками | `web-research` |
| `coder` | Кодер | код, файлы, тесты до рабочего результата | — |
| `sysadmin` | Системщик | Windows, PowerShell, автоматизация рутины | `windows-automation` |

Любой навык можно подключить вручную: `--skill <name>`, `/use <name>` или клавиша `t` в списке навыков меню.

### Автоматический режим (inbox → outbox)

```powershell
.\run.cmd daemon
```

Кладёте в `inbox/` файл `.txt` или `.md` с задачей — агент забирает его, выполняет и пишет отчёт в `outbox/<имя>.md`, а задачу переносит в `inbox/done/`. Файлы, начинающиеся с `_` или `.`, игнорируются.

Полная автономность:

```powershell
.\run.cmd daemon --yes
```

Разово обработать очередь и выйти:

```powershell
.\run.cmd daemon --once
```

Без `--yes` опасные действия (удаление, реестр, системные команды) отклоняются, а безопасные выполняются.

## Как обучать агента

Есть четыре уровня обучения — от простого к сложному.

### 1. Факты (память)

Скажите агенту в чате: «запомни, что я работаю в Excel и люблю краткие ответы» — он вызовет `memory_save`. Или добавьте вручную:

```powershell
.\run.cmd teach "Пользователя зовут Иван, он говорит по-русски"
.\run.cmd memory add "Проект называется Atlas, код на Python" --tags проект,код
.\run.cmd memory search "как зовут"
```

Последние факты автоматически попадают в системный промпт при каждом запуске.

### 2. Навыки (методики)

Навык — это markdown-файл в `skills/` с описанием, как выполнять класс задач. Агент видит каталог навыков и загружает нужный целиком.

Создать вручную:

```powershell
.\run.cmd skill new report-excel --description "Сборка отчётов в Excel" --file .\my-instructions.md
```

Или просто попросить в чате: «Создай навык, как ты должен делать отчёты в Excel: …». Агент сохранит его сам через `save_skill`.

Формат:

```markdown
---
name: report-excel
description: Когда и зачем применять навык
---

# Пошаговая инструкция
1. ...
2. ...
```

Файлы `web-research.md` и `windows-automation.md` — примеры.

### 3. Постоянные правила

В `config.json` есть поле `system_extra` — текст, который добавляется в системный промпт каждой задачи. Например:

```json
"system_extra": "Всегда отвечай по-русски. Все новые проекты создавай в workspace/projects. Не используй глобальные npm-пакеты."
```

### 4. Новые инструменты

Агент расширяется кодом. Создайте `agent/tools/my_tools.py`:

```python
from . import tool

@tool(
    "word_count",
    "Посчитать слова в тексте.",
    {
        "type": "object",
        "properties": {"text": {"type": "string"}},
        "required": ["text"],
    },
)
def word_count(args, ctx):
    return f"Слов: {len(str(args['text']).split())}"
```

И добавьте импорт в конец `agent/tools/__init__.py`:

```python
from . import my_tools  # noqa: F401
```

Инструмент сразу появится у модели. Внутри доступны `ctx.workspace`, `ctx.settings`, `ctx.audit`, `ctx.gate(...)`.

## Безопасность

- **Изоляция рабочей папки.** Файловые инструменты не выпускают за пределы `workspace/`, пока в конфиге не включён `allow_outside_workspace`.
- **Подтверждения.** Режим `confirm: "smart"` (по умолчанию) спрашивает только про опасное: рекурсивное удаление, форматирование, реестр, выключение, запуск скачанного кода и т.п. `"always"` — спрашивать про всё, `"never"` — вообще не спрашивать.
- **Журнал.** Каждый инструмент, подтверждение и ошибка пишутся в `data/audit.log`.
- **Защита web_fetch.** Запрещены обращения к `localhost` и приватным IP, чтобы агент не мог дёргать локальные сервисы.
- **Повторы.** Если модель зациклилась на одном действии, агент останавливает повтор и просит сменить подход.

Важные ограничения:

- `run_shell` — это не полноценная ОС-песочница: команда технически может обратиться к любым файлам пользователя. Опасные шаблоны отсекаются, но 100% гарантии нет. Не запускайте агента с `confirm: "never"` на чужих или недоверенных задачах.
- Качество и безопасность сильно зависят от модели. Слабые модели чаще ошибаются в аргументах.
- Перед экспериментами с важными файлами делайте резервную копию.

## Как это работает

1. Пользователь ставит задачу.
2. Агент отправляет модели системный промпт, историю и список инструментов.
3. Модель либо отвечает текстом, либо просит вызвать инструмент.
4. Агент проверяет безопасность, выполняет инструмент и возвращает результат модели.
5. Цикл повторяется до финального ответа или лимита `max_steps` (задаётся в `config.json`).
6. Если провайдер не умеет native tool calling, автоматически включается текстовый протокол `<tool_call>`.

История диалога и все действия сохраняются в `data/sessions/` и `data/audit.log`.

## Диагностика

| Проблема | Решение |
|---|---|
| `Не удалось подключиться к ...` | запущен ли Ollama/LM Studio; верны ли `base_url` и порт |
| `HTTP 404` | проверь, что в `base_url` есть `/v1` |
| Модель отвечает, но не вызывает инструменты | включи `"native_tools": false` — сработает текстовый протокол |
| Модель выдумывает результаты | возьми модель крупнее и с поддержкой tools |
| `Путь вне рабочей папки запрещён` | работай в `workspace/` или включи `allow_outside_workspace` |
| Медленно | локальная модель меньше по размеру или облачный API |
| Не понимает задачу | разбей на шаги, добавь навык или уточни в `system_extra` |
| Сломалось окружение | удали `.venv` и запусти `setup.ps1` |

Полная проверка: `.\run.cmd doctor`.

## Философия

ATLAS — не «чат с советами», а исполнитель с инструментами и памятью. Чем точнее вы формулируете задачу и чем лучше модель, тем автономнее он работает. Обучайте его фактами и навыками — и он будет делать всё больше без напоминаний.
